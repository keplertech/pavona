# Keplertech tools on Pavona

Scripts to reproduce runs of the [keplertech](https://github.com/keplertech)
tools on the Pavona IP blocks:

- **najaeda**: elaborate each IP's SystemVerilog RTL into a naja netlist
  and report load status and netlist statistics.
- **kepler-formal**: run a sequential equivalence check (SEC) of each IP's
  RTL against itself, measuring how much of each IP the checker can
  elaborate and prove.

Both flows share the same input: a flat file list per IP, generated by
fusesoc from the IP's `.core` file.

## Contents

| File | Purpose |
|---|---|
| `ips.txt` | IP cores to process: `<core VLNV> <top module>` per line |
| `pavona_flist.py` | fusesoc wrapper core -> absolute-path `.flist` per IP |
| `najaeda_sweep.py` | najaeda load of every IP, in default and/or single-unit mode |
| `kepler_sweep.py` | kepler-formal SEC self-check of every IP |
| `requirements.txt` | Python dependencies (najaeda, fusesoc) |

All generated files go to `keplertech/out/`, which git ignores.

## Setup

```sh
python3 -m venv .venv
.venv/bin/pip install -r keplertech/requirements.txt
```

kepler-formal is a separate C++ tool; build it from
<https://github.com/keplertech/kepler-formal> and either put it on `PATH`,
set `KEPLER_FORMAL=/path/to/kepler-formal`, or pass `--kepler`.

## File lists

```sh
.venv/bin/python keplertech/pavona_flist.py            # all IPs
.venv/bin/python keplertech/pavona_flist.py uart aes   # a subset
```

For each IP, the script writes a wrapper core depending on the IP plus the
`top_egret` constant packages (which provide the `lowrisc:virtual_constants:*`
cores), runs `fusesoc run --setup` with the `prim_generic` mapping and
`SYNTHESIS=true`, and rewrites the generated `.vc` into
`out/build/<ip>/<ip>.flist`. If the plain wrapper doesn't resolve, it retries
with the testing `rnd_cnst` / `lc_ctrl_token` packages. File lists are reused
on later runs; delete `out/build/<ip>` to regenerate one.

## najaeda sweep

```sh
.venv/bin/python keplertech/najaeda_sweep.py                  # all IPs, both modes
.venv/bin/python keplertech/najaeda_sweep.py --mode single uart i2c
```

- `default` mode compiles each file as its own compilation unit.
- `single` mode (`SystemVerilogConfig(single_unit=True)`)
  compiles all files as one unit, like Verilator. Some Pavona sources use
  `` `ASSERT `` or `` `PRIM_FLOP_SPARSE_FSM `` without including the file that
  defines them, and only load in this mode.

The script is tied to najaeda 0.7.29, the version used for the results below
(`NAJAEDA_VERSION` in the script, pinned in `requirements.txt`); it stops if
another version is installed.

Each IP is loaded in its own subprocess (`-j 4` by default). Results:
`out/najaeda/<mode>/<ip>/{result.json,naja_sv_diagnostics.log,log.txt}` and
the tables `out/najaeda/summary.md` and `summary.json`.

## kepler-formal sweep

```sh
.venv/bin/python keplertech/kepler_sweep.py --kepler /path/to/kepler-formal -- --sv_single_unit
.venv/bin/python keplertech/kepler_sweep.py uart -- --sv_single_unit --sec-engine k_induction -k 8
```

Each IP is checked with

```sh
kepler-formal -sv --sv_design1_flist <ip>.flist --sv_design1_top <ip> \
                  --sv_design2_flist <ip>.flist --sv_design2_top <ip> -v sec
```

plus any arguments given after `--`. kepler-formal `b9918a3` and later accept
`--sv_single_unit`, the equivalent of najaeda's single-unit mode; pass it so
that acc, spi_host and usbdev load. Results:
`out/kepler/<ip>/{kepler.log,result.json}` and `out/kepler/summary.md`.

Status values:

| status | meaning |
|---|---|
| `proved` | all observed outputs proved equivalent (with the default dual-rail encoding: no binary-defined difference) |
| `partial` | some outputs proved; the rest skipped by extraction limits or left inconclusive by the engine |
| `not_equivalent` | counterexample found (should never happen for a self-check) |
| `inconclusive` | no proof and no counterexample |
| `load_fail` | the SystemVerilog frontend rejected the design |
| `timeout` | exceeded `--timeout` (900 s by default) |
| `error` | anything else; see `kepler.log` |

Runs are serial by default. When 4 runs went in parallel, some failed at
once with a garbled "No such file or directory" error and then passed when
rerun alone.

kepler-formal bundles its own naja build, so its SystemVerilog support can
lag behind the najaeda release used by `najaeda_sweep.py`. `kepler-formal
--version` prints the bundled naja version, and the summary records it.

Build kepler-formal with `-DCMAKE_BUILD_TYPE=Release`: a non-Release build
made the sweep about 11x slower and pushed keymgr_dpe past the timeout.

If `PYTHONPATH` points at a local naja build tree, it shadows the najaeda
installed in the venv; unset it to measure the installed release.

**Summary:** 26 of 28 IPs load; 14 fully proved, 12 partially; 11,304 of
13,234 outputs proved (85.4%) in about 27 minutes. No output was found to
differ.

Columns:

- **primitives**, **load (s)**: najaeda netlist size and load time
  (single-unit mode).
- **kepler-formal**, **outputs proved**, **time (s)**: SEC result.
- **why not 100%**, the reason some outputs have no verdict:
  - *skipped: net driver issue*: kepler-formal drops the logic cone because
    a net in it has no driver or several drivers in the elaborated netlist.
    This points at a SystemVerilog frontend issue, not a design difference.
  - *skipped: clock-gate latch*: the outputs sit behind a latch, which SEC
    doesn't support yet.
  - *inconclusive*: the proof engine (PDR) ran but reached no verdict.
  - *load fail*: see [Known Pavona-side issues](#known-pavona-side-issues).

¹ Loads only in single-unit mode (najaeda `single_unit=True`, kepler-formal
`--sv_single_unit`): the sources use `` `ASSERT `` or
`` `PRIM_FLOP_SPARSE_FSM `` without including the file that defines them.

### Run setup

Run on the fork's `main` at `cfe8d1f`, on macOS (Apple silicon), with:

- najaeda 0.7.29 (PyPI), fusesoc file lists as described above (2026-10-14);
- kepler-formal 0.5.0 (git `c7bf059`, Release build), which bundles naja
  0.7.29 (`3da8811d`), `--sv_single_unit`, default SEC settings (PDR engine,
  dual-rail encoding, max k 32), 900 s timeout, one IP at a time (2026-10-15).

Reproduce with `najaeda_sweep.py` and `kepler_sweep.py`; the raw tables are in
`out/najaeda/summary.md` and `out/kepler/summary.md`.

## Known Pavona-side issues

- `otp_macro`: `hw/ip/otp_macro/otp_macro.core` doesn't list dependencies its
  RTL uses (`lowrisc:ip:tlul`, `lowrisc:prim:subreg`,
  `lowrisc:prim:sparse_fsm`, `lowrisc:prim:sec_anchor`,
  `lowrisc:prim:reg_we_check`), so it fails standalone with unknown modules.
- `ascon`: slang rejects implicit conversions to enum types (for example
  `logic[2:0]` to `duplex_op_e` in `ascon_core.sv`).
- `acc`, `spi_host`, `usbdev`: only load in single-unit mode (najaeda
  `single_unit=True`, kepler-formal `--sv_single_unit`), see above.
